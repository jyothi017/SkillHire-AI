Project abstract

DELIVERABLE 1

Interview question sets are often written in a hurry. They can miss important skills, repeat the same idea, and come with no way to score the answers. This study shows how carefully written prompts help people use general AI chat tools to prepare better question sets.

It covers four tasks: generating questions for a job role, checking skill coverage, finding duplicate questions, and writing scoring rubrics. Each prompt is compared with a simpler first version on the same input, then improved. A person must review every question and rubric before use. No software is built. Everything works by typing prompts into an AI chat tool.

Problem statement

DELIVERABLE 2

Placement teams, trainers, and recruiters need many question sets for many roles. Writing them by hand takes time. Asking an AI for "10 questions for a Java developer" is fast, but the result is hard to trust.

  • The questions may ignore some required skills.
  • The same idea may appear several times in different words.
  • Difficulty may be uneven for the level.
  • There is no scoring guide, so two interviewers may score the same answer differently.
  • The result changes every time because the request was loose.

Objectives

DELIVERABLE 3
  • Show how better prompt design improves quality, consistency, and usefulness.
  • Give reusable prompts that work for any job role.
  • Report skill coverage honestly. One passing mention is not full assessment.
  • Find exact, similar, and near-identical questions.
  • Produce clear 1 to 5 scoring rubrics.
  • Test each prompt against a simpler one on the same input.
  • Keep a human in charge of every final decision.

In scope

  • Prompt design and prompt testing
  • Output evaluation and prompt improvement
  • Roles such as Java, Python, Cloud, Data Analyst, Web, or any role you supply
  • A human review stage

Out of scope

  • Building software, a web application, or writing program code
  • Any database, API, backend, or frontend
  • Scoring real candidates or making hiring decisions
DELIVERABLE 4 · EXISTING APPROACH

Write by hand or ask loosely

  • Questions copied from old papers or websites
  • One-line AI requests with no rules
  • No check for skill gaps or repeats
  • Scoring decided on the spot
PROPOSED APPROACH

Structured prompts in a chain

  • One master prompt collects six details first
  • Four task prompts, each with rules and a fixed output format
  • Each prompt is tested and improved on the same input
  • A person reviews everything before use

Prompt-engineering workflow

Seven steps, in this order
  1. Collect role detailsThe master prompt asks for job role, skills, level, round, number of questions, and question types.
  2. Generate questionsA structured prompt writes questions tagged by skill, difficulty, and type.
  3. Check skill coverageA second prompt counts questions per skill and flags gaps.
  4. Find duplicatesA third prompt flags repeated or overlapping questions.
  5. Write rubricsA fourth prompt creates a 1 to 5 scoring guide for each question.
  6. Test and improveRun a simple prompt and an improved prompt on the same input. Score both. Refine.
  7. Human reviewA person checks every question and rubric. AI output never decides hiring.

Techniques used

DELIVERABLE 5
  • Role promptingTell the AI to act as an interviewer or evaluator so the tone and depth fit the job.
  • Input collectionThe AI asks for missing details instead of guessing them.
  • Numbered rulesShort rules are easier for the AI to follow than a long paragraph.
  • Output format controlTables and fixed sections make results easy to compare and check.
  • Negative instructionsSay what not to do, such as "do not call a skill fully assessed from one mention".
  • Uncertainty flagsThe AI marks anything it is unsure about, such as "Needs human check".
  • Prompt chainingThe output of one task becomes the input of the next.
  • Iterative refinementTest, find weaknesses, improve the prompt, test again.
  • Fixed test inputUse the same input for both versions so the comparison is fair.
  • Human in the loopA reviewer checks the output before anyone relies on it.

Rubric example for question 2
            

              
Expected answer points
  • Read the file line by line or in chunks, not all at once.
  • Process each piece, then let it go.
  • Use a context manager so the file closes.
  • Explain why loading everything uses too much memory.
  • Check the fix on a smaller sample first.

              
Scoring scale
  • 1 Cannot suggest a fix.
  • 2 Names the problem, fix is vague.
  • 3 Reads line by line but cannot say why.
  • 4 Correct fix with a clear reason.
  • 5 Correct fix, memory reasoning, chunking, and a way to verify.

              
Common mistakes
  • Suggesting only "add more memory".
  • Loading the whole file into a list first.
  • Forgetting to close the file.

              
Strong and weak signs
  • Strong: explains why memory grows and how streaming avoids it.
  • Weak: guesses at tools without a reason.

Limitations
DELIVERABLE 11

            
    
              
  • AI can state wrong technical facts with confidence. A subject expert must check them.
    • 
              
  • The same prompt can give different results between runs and between AI tools.
    • 
              
  • The AI may count skill coverage wrongly. Count by hand once.
    • 
              
  • The test plan uses only three roles, so it cannot prove results for every role.
    • 
              
  • Examples marked illustrative were written by hand. They are not test results.
    • 
            

          

          

            
Ethical considerations

            
    
              
  • Never make a hiring decision from AI output alone.
    • 
              
  • Check questions for bias in wording, examples, and assumed background.
    • 
              
  • Do not ask about age, gender, religion, nationality, or family.
    • 
              
  • Do not paste candidate details or private company information into an AI tool.
    • 
              
  • Treat rubrics as guides. Accept valid answers that use a different approach.

Conclusion
DELIVERABLE 12

          
This study sets out a method for turning a loose request into a reliable process: collect the details, generate tagged questions, check coverage, remove repeats, write rubrics, and send everything through human review. The prompts are reusable for any role.

          
The study does not yet claim that the improved prompts perform better. That claim depends on the test runs in the plan. Once real scores are entered in the results template, the comparison will show where each improvement helped and where it did not.
